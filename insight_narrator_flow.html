Phase 0

Data Hydration
  • Single DB round-trip collects all data upfront
  • 6 months of monthly KPIs (channels, types, languages)
  • All-time channel health + user performance rollups
  • 90-day raw fact sample for cross-dim/DQ/op risk
  • 30-day insight history for follow-up tracking
  • Dimension lookup tables for human-readable labels

Phase 1 · Analyzer 1

Anomaly Detector
  • Z-score ≥ 2.5 → high, ≥ 1.5 → medium, ≥ 1.0 → low
  • MoM delta ≥ 40% → high, ≥ 25% → medium, ≥ 15% → low
  • IQR outlier detection (multiplier 1.5)
  • Severity is Python-assigned — LLM cannot change it
  • Covers: channels, languages, input/output types

Phase 1 · Analyzer 2

Consecutive Trend Detector
  • Finds metrics moving same direction for 3+ consecutive months
  • Streak ≥ 5 months AND delta ≥ 40% → high severity
  • Generates contextual suggested_action per signal
  • insight_source = "consecutive"

Phase 1 · Analyzer 3

Funnel Analyzer
  • 3-stage funnel: uploaded → processed → published
  • Flags channels with publish_rate 15pp below fleet median
  • Always generates FunnelSummary (for Pipeline tab)
  • FunnelByEntity: per-channel rate, gap, and status

Phase 1 · Analyzer 4

Cross-Dimension Patterns
  • Pairs: channel×output_type, channel×language, user×output_type
  • KL divergence / entropy-based surprise scoring
  • ZEROS: produces 0 of something popular (expansion opp)
  • OVER-INDEXED: 2x+ fleet average (specialization)
  • UNDER-INDEXED: <50% fleet average (growth opp)

Phase 1 · Analyzer 5

Operational Risk Detector
  • Dormant channels: 30+ days no activity (60d → high)
  • SPOF users: sole producer of a content type
  • Concentration risk: top 2 users ≥ 75% of output
  • Ghost users: account exists, 0 output in 60 days

Phase 1 · Analyzer 6

Data Quality Checker
  • Checks: team_id, platform_id, published_url, language_id, input/output type
  • Issue threshold: >10% missing/unknown triggers a signal
  • Duplicate detection: ≥ 1% of video_ids repeated
  • Invalid URL: published flag set but no URL present
  • Always generates DQScorecard with overall_score

Phase 1 · Analyzer 7

Milestone Detector
  • Record-breaking months: 10%+ above previous best
  • First-time threshold crossings (e.g., first 500 videos)
  • Volume milestones: 100, 250, 500, 1000, 2500, 5000
  • Perfect publish rates: first time > 80%
  • Always severity = "low" (positive, balancing signal)

Phase 1.5

Root Cause Decomposition
  • Applied only to channel-level anomaly signals
  • Breaks down by: output_type, user, language
  • Calculates contribution % per sub-dimension driver
  • Stored in signal.root_cause_breakdown[]

Phase 2

Entity Synthesizer
  • Groups signals by (entity_type, entity_id)
  • 3+ signals on same entity → SynthesisBundle
  • Bundle carries combined context and highest severity
  • 1–2 signals → pass through as singles

Phase 3

Follow-Up Tracker
  • Compares current signals against 30-day history
  • new: first time seen · ongoing: seen before
  • worsening: severity increased since last run
  • Unchanged signals seen <7 days ago → suppressed
  • Auto-generates "resolved" signals for recovered issues

Phase 4

Signal Router
  • anomaly / consecutive / cross_dim / milestone → watchlist
  • funnel / op_risk → pipeline
  • dq → data_governance
  • high/med KPI signals → kpi_insights (SparkKPI dots)
  • Auto-generates NLQ queries per signal for "Explore" links

Phase 5

LLM Narration (3 parallel)
  • Urgent: high/med anomalies + worsening — alert tone
  • Analytical: trends, cross-dim, milestones — discovery tone
  • Operational: op risks, DQ, funnel gaps — risk tone
  • LLM constraints: no severity changes, no invented causes, title ≤ 12 words
  • Template card fallback if LLM fails (non-blocking)
  • Separate sequential call for executive digest

Phase 6

Health Scoring
  • publish_rate_score (40%) — vs fleet median
  • activity_score (30%) — month-to-month consistency
  • trend_score (20%) — direction of last 3 months
  • dq_score (10%) — record completeness
  • Grade: A (≥80) · B (60–79) · C (40–59) · D (<40)
  • pulse_score = fleet-wide weighted average

Phase 7

Assembly & Cache
  • Routes InsightCards to 4 tabs + dashboard layer
  • Builds period_summary (MoM metric comparison)
  • Injects FunnelSummary and DQScorecard (always present)
  • Writes to insight_cache (stale-while-revalidate key)
  • Writes to insight_log (one row per card)
  • Updates pg_insight_history for next run's follow-up tracking

Caching Strategy

Stale-While-Revalidate
  • Cache key: narrator:{client_id}
  • Stale threshold: 24 hours (configurable)
  • Fresh hit → return immediately, zero pipeline cost
  • Stale hit → return cached now + refresh in background
  • Cache miss → run full pipeline synchronously
